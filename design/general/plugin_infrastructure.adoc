= TensorRT Plugin Infrastructure
{nbsp}
:description: How Edge-LLM custom TensorRT plugins are structured, registered, and integrated across export, build, and runtime

== Overview

Edge-LLM uses custom TensorRT plugins for operations that are not natively
supported or not efficiently fusible by TensorRT. Each plugin is a
self-contained unit with Python custom-op stubs, ONNX dynamo translations,
a C++ implementation, and builder/runtime integration.

Plugins are implementation details of their parent components. Component
docs explain why a plugin is needed; this document explains the shared
infrastructure and conventions.

== Integration Pattern

Every plugin follows the same three-layer pattern:

[mermaid]
----
graph LR
    PY[Model code + torch.ops.trt_edgellm stubs] -->|torch.onnx.export(dynamo=True)| TRANS[ONNX Script translations]
    TRANS -->|emits trt_edgellm custom op| ONNX[ONNX Graph]
    ONNX -->|deserialized by| CPP[C++ Plugin]
    CPP -->|executes in| TRT[TensorRT Engine]
----

=== Python Export Layer

Plugin-friendly model code calls custom-op stubs from
`tensorrt_edgellm/models/ops.py`. The checkpoint exporter uses
`torch.onnx.export(dynamo=True)`, so plugin lowering is implemented through
ONNX Script translations registered in
`tensorrt_edgellm/onnx/dynamo_translations.py`, with custom operator schemas in
`tensorrt_edgellm/onnx/onnx_custom_schemas.py`.

When adding or changing a plugin, keep the stub, translation, schema, and C++
plugin contract synchronized. Do not use the legacy `torch.onnx` symbolic
registration path; it is not the current Edge-LLM exporter.

=== C++ Plugin Layer

Plugin implementations live under `cpp/plugins/<PluginName>/`. Each
plugin implements:

- `getOutputDimensions` and `getOutputDataTypes` for shape/type inference.
- `configurePlugin` for profile-based configuration.
- `serialize` and `getSerializationSize` for engine serialization.
- Constructors from `PluginFieldCollection` and serialized data.
- `enqueue` for CUDA kernel launch.

All plugins register with TensorRT through the shared Edge-LLM plugin
library.

=== Shared Utilities

`cpp/plugins/utils/pluginUtils.{h,cpp}` provides common helpers for dtype
conversion, workspace allocation, and error checking.

== Code Touchpoints

[cols="1,2"]
|===
| Path | Responsibility

| `tensorrt_edgellm/models/ops.py`
| Python custom-op stubs used by model implementations.

| `tensorrt_edgellm/onnx/dynamo_translations.py`
| ONNX Script translations from `torch.ops.trt_edgellm.*` stubs to custom ONNX operators.

| `tensorrt_edgellm/onnx/onnx_custom_schemas.py`
| Custom ONNX operator schema definitions for the `trt_edgellm` domain.

| `tensorrt_edgellm/onnx/export.py`
| Checkpoint export orchestration using `torch.onnx.export(dynamo=True)`.

| `cpp/plugins/<PluginName>/`
| C++ plugin implementation, headers, sources, and optional CUDA kernels.

| `cpp/plugins/utils/`
| Shared plugin utilities.

| `cpp/CMakeLists.txt`
| Plugin build targets and kernel source registration.
|===
