= Tokenizer Architecture
{nbsp}
:description: Tokenizer and chat-rendering runtime boundaries

== Overview

The tokenizer converts text to token IDs and token IDs back to text. Prompt
rendering is a separate model contract owned by `ChatTemplate`.

== Runtime Artifacts

`tokenizer.json`:: Vocabulary, merges, normalization, pretokenization, and
special-token data consumed by `Tokenizer::loadFromHF(...)`.

`tokenizer_config.json`:: Tokenizer metadata and special-token declarations.

`chat_template.jinja`:: Verbatim model-owned prompt program.

`chat_template.processor`:: Explicit provider raw-processor contract for a
checkpoint whose Jinja expects preprocessed message content.

`chat_template.model`:: Explicit model-specific manual renderer selection for
a family that does not provide Jinja semantics.

== Architecture

[mermaid]
----
flowchart LR
    REQ[Structured messages, media, reasoning, tools] --> CT[C++ ChatTemplate / Pantor Inja]
    CT --> TXT[Formatted prompt]
    TJ[tokenizer.json] --> TOK[C++ Tokenizer]
    TC[tokenizer_config.json] --> TOK
    TXT --> TOK
    TOK --> IDS[Token IDs]
----

The server forwards the structured request to C++; it does not preformat tool
messages in Python. The provider template defines role ordering, any system
text, media placeholders, reasoning markers, tool syntax, and generation
prompts. `Tokenizer` never interprets those semantics.

== Export

Export preserves tokenizer artifacts and copies the provider's default Jinja
template verbatim. If it is embedded in `processor_config.json` or
`tokenizer_config.json`, export materializes the same string as
`chat_template.jinja`. The C++ runtime passes that file directly to Pantor
Inja. Named template sets and unsupported syntax fail explicitly.

== Encode and Decode

Encoding partitions special tokens, applies the configured pretokenizer and
token encoder, and resolves vocabulary IDs. Decode performs the reverse mapping
and preserves streaming UTF-8 behavior. These paths operate only on formatted
text and have no model-specific chat logic.

== Code Touchpoints

[cols="2,3", options="header"]
|===
| File | Responsibilities

| `cpp/chatTemplate/chatTemplate.{h,cpp}`
| Structured request context, explicit raw-processor contracts, and Pantor
Inja rendering.

| `cpp/tokenizer/tokenizer.{h,cpp}`
| Tokenizer loading, encoding, decoding, and special tokens.

| `tensorrt_edgellm/chat_template.py`
| Strict provider-template extraction and explicit native contract selection.
|===

== Testing

- Provider `apply_chat_template(..., tokenize=False)` versus C++ output.
- Text, multimodal, reasoning, tool-call, and tool-result scenarios.
- Source tokenizer versus exported tokenizer ID parity.
- Deterministic inference sanity after prompt and tokenizer parity pass.
