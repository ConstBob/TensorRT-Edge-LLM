= Prefix KV Reuse
{nbsp}
:description: System-prompt/prefix KV reuse flow and runtime integration

== Overview

Prefix KV reuse avoids recomputing key/value states for repeated prompt
prefixes, such as system prompts. On a cache hit, runtime injects saved
KV into the active decoder cache and only runs prefill on the remaining
suffix tokens.

This document assumes generic KV terms from link:README.adoc[kv_cache/README.adoc]
and baseline decoder KV from link:decoder.adoc[decoder.adoc].

| Yes

== Design

=== Data Model

Runtime stores cached prompt entries keyed by prompt content and LoRA
context. Each entry contains tokenized prompt content, KV tensor data,
and effective prefill/reuse lengths.

=== Runtime Flow

On request setup, runtime looks up prefix KV. On a hit, cached KV is
instantiated into the active batch slot and `reuseKVCacheLengths` is
recorded per sequence. `HybridCacheManager::resetForNewSequences(...)`
initializes active lengths from reused lengths. Prefill then computes
only the remaining suffix tokens.

Prefix reuse seeds the decoder KV cache; it does not replace the normal
per-layer decoder KV flow.

=== Invariants

* Reuse length is always <= total prompt length and zero on a miss.
* Cached KV tensor must match model dtype, KV head count, head dimension,
  layer count, and LoRA context.
* Reuse must not change generated output relative to a full-prefill run.

== Testing

Prefix reuse is validated through pipeline tests exercising cache-hit and
cache-miss paths. Correctness is confirmed by comparing reuse-enabled
and reuse-disabled outputs for the same prompt. Cache capture/restore
behavior is unit-tested in `unittests/hybridCacheManagerTests.cpp`;
pipeline lists live under `tests/test_lists/l0_pipeline_*.yml`.
