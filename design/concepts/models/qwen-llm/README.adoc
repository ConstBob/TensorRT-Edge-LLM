= Qwen Decoder Architecture
{nbsp}
:description: Architecture notes and implementation pointers for Qwen-family decoder checkpoints in TensorRT Edge-LLM

== Overview

Qwen decoder checkpoints cover dense Qwen2/Qwen2.5/Qwen3 models,
Qwen-derived reasoning distills, Qwen3 sparse-MoE variants, and Qwen3.5
hybrid checkpoints. Dense Qwen models use the default decoder exporter. Qwen3
MoE registers a custom `qwen3_moe` handler for routed FFNs. Qwen3.5 registers
specialized dense and MoE handlers because its decoder alternates between
GatedDeltaNet linear-attention layers and gated full-attention layers.

== Edge-LLM Integration Notes

* DeepSeek-R1 distilled Qwen checkpoints are treated as Qwen decoder
  architecture. Their reasoning behavior is checkpoint/template-specific, not a
  separate decoder implementation.
* Qwen3 adds attention-head Q/K normalization and thinking-mode template
  behavior; keep those notes at the template or attention boundary instead of
  creating a separate support list.
* Qwen3 MoE replaces the dense FFN position with routed experts and the
  `Int4MoePlugin`; the reusable contract is documented under
  link:../../components/moe/[MoE / routed experts].
* Qwen3.5 uses `layer_types` to select either `full_attention` or
  `linear_attention` (GDN) per decoder layer. Its recurrent-state contract is
  documented under link:../../components/state_space/linear.adoc[Linear Attention / Gated Delta Net].
* Qwen3.5 dense MTP draft export is implemented as a dedicated draft model;
  the base hybrid decoder remains the verification model.
* Cosmos-style Qwen3 decoders should point back here for text-decoder details
  and to link:../qwen-vl/[Qwen vision-language] for modality packaging.
