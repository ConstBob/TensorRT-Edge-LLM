= Edge-LLM Architecture Design Documents
{nbsp}
:description: Top-level index and reference architecture for TensorRT Edge-LLM component designs

== Purpose

This directory contains architecture and design documents for TensorRT Edge-LLM.
The tree is organized around reusable components, model-family communication
pages, and cross-cutting implementation notes:

[cols="1,3"]
|===
| Directory | Purpose

| link:concepts/components/[concepts/components/]
| Reusable component designs. Each component page explains why the component is
needed and how it is implemented in Edge-LLM.

| link:concepts/models/[concepts/models/]
| Family-level model communication docs. Each family page makes it easy to see
related components, implementation entry points, the high-level architecture,
and the HF profiles for supported variants.

| link:llm/[llm/]
| LLM loader and model-construction design notes. This is not a component
directory.

| link:general/[general/]
| Cross-cutting design principles and API/plugin guidelines.

| link:in_progress/[in_progress/]
| Work-in-progress proposals that are not accepted as mainline design docs yet.
|===

== Component Index

[cols="1,3"]
|===
| Component | Scope

| link:concepts/components/tokenizer/[tokenizer/] | Tokenizer artifacts, chat templates, and encode/decode boundaries.
| link:concepts/components/embeddings/[embeddings/] | Token, multimodal, and deepstack embedding input contracts.
| link:concepts/components/vision/[vision/] | Image/video preprocessing, visual encoder export, and VLM runtime embedding generation.
| link:concepts/components/audio/[audio/] | Audio workflow index with separate ASR and TTS component pages.
| link:concepts/components/positional_encoding/[positional_encoding/] | RoPE-family position caches and MRoPE when configured.
| link:concepts/components/normalization/[normalization/] | Pre-attention, pre-FFN, and final norm placement.
| link:concepts/components/attention/[attention/] | Causal self-attention and plugin/TRT-native binding contract.
| link:concepts/components/kv_cache/[kv_cache/] | Prefill/decode cache lifecycle and prefix reuse.
| link:concepts/components/state_space/[state_space/] | State-space and linear-attention sequence mixing with recurrent state cache for hybrid decoders.
| link:concepts/components/ffn/[ffn/] | Dense, gated, and quantized MLP position in decoder blocks.
| link:concepts/components/moe/[moe/] | Routed expert layers, INT4/NVFP4 precision paths, and hardware-specific MoE kernels.
| link:concepts/components/residual/[residual/] | Skip-path additions around attention, FFN, MoE, and state-space sublayers.
|===

Component directories under `concepts/components/` follow a two-level structure:

- `README.adoc` describes the generic component contract (Level 1).
- Variant documents describe reusable component permutations (Level 2).

Model-architecture READMEs under `concepts/models/` stay brief. They summarize
architecture-specific notes, link to reusable component docs and implementation
pointers, and defer the checkpoint support matrix to
link:../docs/source/user_guide/getting_started/supported-models.md[Supported Models].

See link:CONTRIBUTING.adoc[Contributing Design Documents] for component
methodology, model-architecture format, size guidance, validation rules, and review checklist.

== Edge-LLM Pipeline Stages

Every model passes through these stages regardless of architecture:

[mermaid]
----
graph LR
    CKPT[Model Checkpoint] -->|export_llm_model| EXPORT[ONNX Model]
    EXPORT -->|llm_build| BUILD[TensorRT Engine]
    BUILD -->|llm_inference| OUT[Generated Tokens]
----

Design documents describe component behavior across export, build, and
runtime stages where applicable.
